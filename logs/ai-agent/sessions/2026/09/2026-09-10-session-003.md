## Work Done

Discovered requirement (1) already existed and was undocumented:
`CaptureScreen.kt` has a `SphereGuideOverlay` that projects the 24 world-
fixed targets onto the screen via real perspective math every frame —
already gives the "dots fixed in space" AR effect. Documentation from
session-001 missed this because `CaptureScreen.kt` wasn't read then.

Implemented (2) and (3):

- `GyroscopeManager.kt`: `DeviceOrientation` now also carries the raw
  (unsmoothed) device→world rotation matrix, copied per event.
- `CaptureViewModel.kt`: `FrameTarget.capturedRotationMatrix` stores the
  real orientation matrix at shutter time. New `startAutoCapture()`
  polls alignment and fires `capturePhoto()` after a 350ms stable hold
  (`CaptureState.holdProgress` drives UI feedback); manual shutter stays
  as fallback. New `setMeasuredHFov`/`CaptureState.measuredHFovDeg`.
- `StitchingEngine.kt`: `FrameInput` now carries the rotation matrix
  instead of azimuth/pitch; per-frame camera basis (right/up/fwd) is
  derived from that matrix (`cameraBasisFromRotationMatrix`) instead of
  an azimuth/pitch reconstruction that assumed zero roll — this is the
  core accuracy fix, since a tilted/rolled phone during capture previously
  produced wrong poses. `stitch()` takes an `hFovDeg` parameter.
- `CaptureScreen.kt`: `measureHorizontalFovDeg` reads the bound camera's
  real FOV via `Camera2CameraInfo`/`CameraCharacteristics` (needs
  `@OptIn(ExperimentalCamera2Interop::class)` — added), fed into both the
  AR overlay and the stitch call; wired `startAutoCapture` via
  `LaunchedEffect(Unit)`; added a hold-progress indicator; labeled the
  manual shutter as a fallback.

Updated docs to match (architecture, module docs, requirements, two
android-native rules files) and fixed the session-001 documentation gap
about the AR overlay.
